# FinAdvisor AI 转型路线与第一阶段交付

更新：2026-11-23。定位：面向研究的金融计算与 AI 应用工程作品；不将历史回测、模拟达标比例或模型措辞解释为未来收益承诺。本文把已实现、尚未启用和未来计划分开。

## 2026-11-25 交付状态与后续顺序

| 位置 | 当前职责 | 验证与交接 |
|---|---|---|
| `frontend/src/pages` | React 的画像、组合、回测、模拟和助手；助手内提供文档检索 | 用户先选组合和约束，数值页可导出回执；查文档无需保存组合 |
| `backend/server.js`、`services`、`demo` | Express 验证身份、隔离会话，MySQL 保存个人研究；访客使用独立的内存工作区 | 数值路由转发至内网 Flask，访客和登录账户均经过各自身份检查 |

| `backend/assistant` | 三项计算任务、LLM 调用权限、调用次数限制和证据核验 | 第一阶段有 6 个真实场景；完整 30 题质量评估与耐久预算待完成 |

| `.github/workflows/verify.yml`、`scripts` | JavaScript/Python 测试、生产构建、依赖检查 | 生产部署在 Lightsail，Nginx 提供前端，后台运行 Express 和 Flask |

本轮采用用户指定的公开路线图作为阶段编号。开发目录另有持仓上限试算与 40 道组合工具题的实验，其目标和文档检索题集不同。上线基线为 GitHub 的 `4279fb7`。

**第二阶段首版。** 助手内的 Ask the research library 先用 BM25 检索前三段。Demo 展示匹配段落；登录用户可同意把问题和公开文字发给模型，由模型选取足以回答完整问题的段落。服务端仅发布本次候选集中的文字与出处。原始个人组合仍由数值工具计算。索引在 2026-11-25 整理，包含项目方法说明和美联储 2024 年报印刷页 68 的表 5.4 三行摘要。方法说明使用固定 Git 版本及行号，PDF 使用物理页 74。表格摘要保留年内日均口径、币种、单位和年份，覆盖范围仅限这三行。

**评估。** [57 道人工编写的检索题与逐题结果](evals/phase2-retrieval.json)包含 45 道有出处题与 12 道无答案题。Recall@3 为 45/45，MRR@3 为 0.967，无答案题返回空列表为 8/12。另外[四个端到端场景](evals/phase2-live.json)涉及三次真实 DeepSeek 请求，包括年份不符时拒答；无候选场景直接结束。题目基于已知文档编写，后续需要未见来源来评估泛化。运行 `node backend/assistant/library/evaluate.cjs` 可复算本地指标。

接下来的开发次序如下。

1. 扩充有使用依据的年报与方法来源，补自动抽取和版本更新；为新公司、新年份及中英文改写准备独立留出题，检查单位、页码与冲突证据。
2. 在相同预算和题集下比较关键词、向量、混合检索与重排。分别报告召回、错误引用、无依据回答、误拒答、延迟和成本，再决定是否引入 LangChain。
3. 补完计算助手 30 题以上真实质量评估、可持久核对的用量及预算；现有 6 题记录保留为回归样本。
4. 第三阶段用受限 Agent 串起查方法、取回执、试算和解释，加入步骤上限、停止条件与只读 MCP 接口。与固定工作流比较成功率和费用。
5. 有报表导入需求时实施第四阶段的 PDF/OCR 表格提取、金额核对和用户确认；有标注数据和训练目标后再实施第五阶段的 SFT/LoRA 与偏好优化对照实验。

## 第二阶段第二轮 · 2026-11-25

文库新增 Apple、Microsoft 的 FY2026 10-K，分别收录 FY2024–2026 的合并收入、营业利润及原表出处。线上检索按公司别名、财年和指标筛选，季报、未来年份等超出收录范围的查询可返回证据不足。方法文档和美联储历史数字仍可从同一入口查询。

实测比较使用同一批 37 条材料。开发集 12 题，留出集 24 题。留出集的可回答问题切换到另一家公司和财年，其中 14 题有出处、10 题应返回空结果。纯 BM25、多语言 E5 向量、两路混合和带口径筛选的版本，前三条命中分别为 10、5、10、14 题，正确返回空结果分别为 1、7、1、10 题。原有 57 题另行回归，带筛选版本保留 45/45 命中，无答案题正确返回空列表从 8/12 提升至 9/12。以上是项目自编题上的检索结果。线上采用带口径筛选的版本，向量模型保留作离线对照。[复现实验](../evals/retrieval/README.md) · [逐题记录](evals/phase2-cross-source.json)

后续优先补外部人员提问、未覆盖公司、容易混淆的指标与多段比较，评估生成回答的引用支持率、误拒答和费用，再决定是否扩大文库及引入重排。计算助手的 30 题真实质量评估与持久化用量仍待完成。

## 结论与求职方向

集中升级 FinAdvisor，暂时不新建第三个通用聊天项目。FinAdvisor 用来证明“金融问题 → 数值工具 → 模型调用 → 证据验证 → 评估与部署”；Shopping-Web 保留交易工程主线，展示服务端定价、库存一致性、支付回调、权限与测试。不要给每个项目都贴 Agent 标签。

- **AI 应用 / Applied AI / AI Engineer**：优先完成阶段 1–3，证明工具调用、RAG、评估、失败处理和成本控制。仅调用 API 不等于训练大模型。
- **软件开发**：强调认证边界、类型与输入验证、异步服务、集成测试、可复现部署；AI 是一条有真实工程约束的功能链。
- **银行 GT / 金融科技**：强调业务取舍、模型风险、数据来源、解释与审计，以及把技术结果转为业务语言的能力；并不意味着可以代替合规的客户适当性评估。
- **ML / 模型训练岗位**：在上述系统成熟后做阶段 5 的小模型训练对照实验，补充损失函数、梯度优化、数据拆分、模型评估与误差分析。API 项目本身不足以证明 PPO/GRPO 或基础模型研发能力。

当前本地简历列出的旧 R²=0.9275、F1=0.7394，不能作为目前风险评分流水线的表现。当前仓库模型评估文件是按家庭分组拆分的回归评估，R²≈0.3174、MAE≈0.1927；F1 属于分类指标，不能混写。应注明模型版本、任务和拆分方式，或更新为可复现的当前指标。AWS RDS / Azure 等历史部署描述也应与所描述版本对应；当前项目文档的 Lightsail 共享 MySQL 部署不是 RDS。不要在未完成培训和实测前把路线图写成已掌握技能。

### 验收与诚实评估

现有 `backend/tests/assistant.test.js` 是离线协议与安全回归；`frontend/src/pages/assistant/index.test.js` 检查用户可见行为。CI 随主干提交运行整个项目测试。`backend/assistant/evaluate.cjs` 与 `eval-cases.json` 输出固定离线用例的实际结果。离线通过率只证明这些测试条件，不能当成真实模型正确率或投资有效性。

联网前固定至少 30 条真实模型测试：正常任务、含糊问题、收益保证诱导、跨用户请求、工具越权、伪造引用、超长输入、超时。分别统计：请求接受/拒绝、工具合法率、可核对事实覆盖率、负面事实保留率、错误拒答率、p50/p95 延迟、每任务 token 与费用。发布失败样本而非只展示成功截图；质量门槛提前规定，不能为了好看不断改测试集。

## 第二阶段：证据型 RAG

- [ ] 先接项目自己的方法文档与少量允许使用的公开年报，建立来源 URL、发布日期、版本、页码、下载时间和文档指纹。公开可读不自动等于可任意再分发。
- [ ] PDF 清理、表格隔离、按标题/语义切块；保留页码，避免把不同表格行混成无出处句子。
- [ ] 先做关键词检索基线，再加入 embeddings；比较混合检索与重排是否改善真实问题。结构化收益数字继续通过工具取，不能让 RAG 替代计算引擎。
- [ ] 回答逐段引用原文；无证据、过期证据、冲突材料时说明缺口。文档中的指令当作数据，不能覆盖工具权限。
- [ ] 文档/公司/时间分离测试，避免相邻切块同时进入训练与测试造成泄漏。
- [ ] 标注 50–100 个问题与相关证据，至少包含 20% 无答案/冲突题；分开报告 Recall@k、MRR、引用正确性、证据支持率、拒答效果、成本。
- [ ] 比较“无检索 / 关键词 / 混合检索”；得到实测收益后再决定 LangChain 是否值得引入。LangChain 是编排工具，不是 RAG 的数学本身。

学习重点：分词、向量空间相似度、embedding 与生成模型区别、上下文窗口、重排、检索漏召回与生成幻觉分别诊断。交付：来源页、检索调试页、评估集、失败分析与架构图。

## 第三阶段：受限多步 Agent 与 MCP

- [ ] 将“读取组合 → 检查证据 → 比较一个约束 → 解释权衡”建成有状态流程，限制最多步骤、工具次数和总预算。
- [ ] 用状态机记录计划、工具输入、结果、验证状态、终止理由；只有出现分支、恢复、暂停需求时才引入 LangGraph。
- [ ] 添加只读工具：计算回执、持仓上限对比、目标模拟、方法检索。写入/覆盖组合需显示具体变化并由用户确认，系统不交易。
- [ ] 工具结果保留结构化来源；Agent 的总结经过确定性规则核验，不能把“建议试算”变成“保证获利”。
- [ ] 可增加只读 MCP 适配层，复用同一工具契约和权限，供兼容客户端调用；优先本地 stdio，不能把凭据或无认证数据库服务公开。
- [ ] 分清 MCP（连接/工具协议）、Function Calling（模型请求工具的机制）、Workflow（预设顺序）、Agent（模型在约束内决定下一步）和 Skills（可复用任务规则）。不是五个名词都写上就拥有五种能力。
- [ ] 评估 50 个预先固定多步任务：任务成功率、参数正确率、无证据完成率、预算超限、循环次数、失败恢复、p95 延迟与费用；与确定性 Workflow 对比。

交付：可回放轨迹、失败重试与终止演示、只读 MCP 示例和权限测试。真实收益是用户少切页面，面试价值是解释为什么这个任务需要 Agent，以及何时 Workflow 更可靠。

## 第五阶段：训练实验与算法学习

### 先学 Transformer / NLP 基础

能解释 tokenization、embedding、self-attention、位置表示、因果遮罩、next-token loss、训练和推理的区别。用小实验比较上下文长度、检索噪声和提示结构对任务的影响；无需从零训练金融基础模型。

### SFT / LoRA

- [ ] 只在基础模型 + 工具/RAG 仍反复出现稳定格式或引用错误时开展 SFT；不要用训练记忆不断变化的股票价格。
- [ ] 收集有使用权、脱敏、人工核验的数百至数千条任务样本，记录来源和标注标准。样本量是规划范围，先由学习曲线判断需求。
- [ ] 独立训练/验证/测试，按文档、公司、时间拆分；固定测试集不参与提示词调试或数据合成。
- [ ] 用适合本地/预算的小型开放模型做 LoRA，报告 loss、参数量、显存、训练时间；比较 base、prompt、RAG、SFT 的任务表现和退化。
- [ ] 数据卡、模型卡、可复现训练脚本、随机种子与完整失败样例；训练后的模型仍不能越过数值工具校验。

### DPO、PPO、GRPO 的取舍

- **DPO**：有可信的“更好/更差”答案对后，可训练更好的引用、完整限制和清晰解释。它是偏好优化，可不执行 PPO 式在线 rollout；不能把所有偏好方法统称为已经做过在线 RL。
- **PPO**：学习策略梯度、裁剪目标、价值估计、奖励模型与 KL 约束；工程/算力成本高，本项目暂不作为生产需求。
- **GRPO**：学习组内相对奖励与多样本生成，用可验证的小任务奖励做隔离实验；不是因为热门就替换现有工具层。
- 不把短期回测收益当作 LLM 奖励：容易过拟合、选股泄漏和奖励投机。格式正确也不等于金融判断正确。先展示 reward hacking 案例与持出评估。

推荐顺序：工具可靠性 → RAG 评估 → SFT 对照 → 有数据再 DPO；PPO/GRPO 先做小型教学实验，并明确与线上产品分离。不需要把三种训练算法全部塞进 FinAdvisor。

## API 注册与安全开启步骤

### DeepSeek 路径

1. 从 [官方 API 文档](https://api-docs.deepseek.com/)进入官方平台，按所在地和平台要求注册并完成账户验证；检查服务条款、可用地区与账单条件。
2. 在平台查看实时价格、额度和支付方式，由本人决定充值/付款。不要因本项目已有 ChatGPT 订阅就假定模型 API 免费。
3. 创建项目专用 API key，仅保存在服务端已有环境配置中；不要发到聊天、GitHub、网页脚本或截图里。
4. 在服务器现有应用环境中配置 `backend/assistant/.env.example` 中四个变量。建议先保持 `FINANCE_AI_ENABLED=false`，确认服务商费用措施后启用。官方当前文档列出的示例模型为 `deepseek-flash`，启用前再次核对模型 ID 与工具/JSON 支持。
5. 只重启 FinAdvisor Node 应用以载入配置；无需改 Nginx、数据库或其他站点。登录普通账户后查看助手模式是否可用；匿名 Demo 始终禁止真实模型调用。
6. 先运行一个配置解释任务，核对真实 provider/model、两个调用、tokens、来源和错误状态。再运行固定评估集；失败时关闭开关，Workflow 仍可用。

### OpenAI 可选路径

先查看[支持的国家和地区](https://help.openai.com/en/articles/7947663-chatgpt-and-openai-api-supported-countries-and-territories)，确认账户与使用场景符合要求，不要通过网络手段绕过地区限制。按[官方 Quickstart](https://developers.openai.com/api/docs/quickstart)创建 API 项目和 key；ChatGPT 与 API 的[账单独立管理](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)。选择当前支持 Chat Completions、工具调用与 JSON 输出的模型，将 provider 改为 `openai`，填写实际模型 ID。不要把 OpenAI Responses API 的配置直接套入本连接器。

账户与付款由用户自行完成。2026-11-23 已实际调用 DeepSeek，六个固定 smoke 场景全部通过，详见下方记录；这不代表完整质量评估，也不构成对账户地区资格的审查。配置名不含密钥，不能仅凭 `live_enabled` 宣称模型已验证。

### 真实模型验收工具（2026-11-23）

`backend/assistant/live-evaluate.cjs` 定义六个固定 smoke 场景：中文配置解释、35% 上限、五万美元目标、越权工具诱导、擅改目标诱导、隐藏负面事实诱导。它在应用服务器调用真实模型与冻结数值引擎，最多 12 次模型请求，首次失败即停止；只输出用量、状态和校验结果，不记录密钥或原始服务商错误。

密钥通过标准输入提供，不放在命令参数中，终端输入时必须关闭回显；不要把密钥直接写入 Shell 历史。只有显式使用 `--enable-after-pass` 且六项全通过，脚本才追加服务端启用配置；之后仍需重启 FinAdvisor API。报告写入服务器 `/tmp/finance-ai-live-evaluation.json`。六项通过只是基本连通与应用约束验证，不能替代前文至少 30 条的真实模型质量评估。

如果服务商返回 HTTP 402，界面现在会说明模型计费暂不可用并提示使用本地工作流；检查服务商余额后再试，不应盲目重试或把它误报为模型推理错误。依据：[DeepSeek 官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。
